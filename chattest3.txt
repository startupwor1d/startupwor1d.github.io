Coding Standards

To keep the project maintainable, let's follow a few rules:

One class per file.
Engine.js coordinates systems only—it shouldn't contain detailed game logic.
All game data (quests, NPCs, buildings, problems) lives in separate data files.
UI panels never draw themselves directly from game logic; a UIManager controls visibility and layout.
New features should plug into existing systems rather than adding more conditionals to the engine.
I also suggest we start using Git properly

A simple commit history will make it much easier to experiment:

main
│
├── v0.1 Initial engine
├── v0.2 UI refactor
├── v0.3 Sprite rendering
├── v0.4 Living city
├── v0.5 Startup gameplay
└── v1.0 First playable release

That way, if a change breaks something, you can always roll back to the last working version.

Notice that Engine never contains game logic.

Instead it becomes something like:

update(dt) {
    this.input.update(dt);

    this.world.update(dt);

    this.entities.update(dt);

    this.company.update(dt);

    this.ui.update(dt);

    this.camera.update(dt);
}

render() {
    this.renderer.begin();

    this.world.draw();

    this.entities.draw();

    this.ui.draw();

    this.renderer.end();
}
